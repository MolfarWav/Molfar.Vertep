## #352 THE LOCAL EMBEDDINGS MODEL RUNS IN A PROCESS OF ITS OWN (2026-11-10; branch `claude/embed-child-process`, not merged, NOT released)
The owner closed a scene by hand and the whole engine died: Bun 1.4.2 on Windows, `panic: NAPI FATAL ERROR napi_define_properties`, the report names `onnxruntime_binding.node`, about 3 h of uptime. **Cause (a reading of the code, not reproduced):** the model lived in a Bun Worker that `release()` terminated after 10 idle minutes; the next embed made a new Worker, which loads the native addon a second time in the same process. **Fix:** `childEngine` in `src/embed-local/index.ts` runs the model in a separate Bun process (`CHILD_SOURCE` in `worker-source.ts`, written to `<data>/embed-local/model-process.mjs`; one JSON per line on stdin, answers on stdout behind a  mark, so library chatter is ignored; environment scrubbed of keys; it ends when stdin closes). If it dies every waiting call fails with its last stderr lines and `LocalEngine.alive()` turns false, so `ensureLoaded` starts a fresh process; a native crash now costs only the embedding, and idle release really frees the memory. **Checks:** 2 new tests in `test/embed-local.test.ts` (real child process with a stub library: embeds, ignores stdout noise, a crash fails the call and the next call works); typecheck; the full suite has the same 32 failures with and without the change (Windows: symlinks, tar, file modes, git). **Not checked:** the real runtime (transformers.js and onnxruntime) on Windows through the new process, the 10-minute idle cycle for real, memory after release. Worth one manual run before the release: embed, wait 11 minutes, embed again.
