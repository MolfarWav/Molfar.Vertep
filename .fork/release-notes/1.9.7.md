# 🧬 Molfar Vertep 1.9.7

A small engine release: long chats on a limited context window no longer get empty replies.

## 🛠️ Fixes
- **Empty or 3-token replies on a full context window.** With the window set to 64k (or any size the chat had outgrown), a long Roleplay chat failed or answered with a handful of tokens, while the same chat worked with the window unlocked. The model library lowers the reply limit of each request to what remains of the window after its own estimate and a 4096-token margin, never below 1. Roleplay already trims the prompt to the window minus the reply, so the extra margin left nothing and the request went out asking for **1 token**. The engine now sends the reply limit the app asks for, as it is. Checked on the six prompt snapshots from the report: the 66k, 85k, 95k and 100k ones would have been sent with 1 token, the 110k and unlocked ones with 4000, which are the ones that worked. The built-in agent keeps its own limit. If a prompt really is larger than the window, the provider now says so instead of the reply silently shrinking.
- Known and left: the engine's token estimate is about 25% higher than the real count for some models (Gemini: 99k estimated, 79k real), so a trimmed chat keeps somewhat less history than the window would take.

## Other changes
- Plugins: a new optional `insertCeiling` hook, so a plugin can report how many prompt tokens it may add to a chat (#217). Nothing uses it yet.

## How to get it
From source: `git pull && bun install && (cd client-agent && bun install) && bun run build:client`, then restart. Downloads and the Android APK are on this release page. See [CHANGELOG.md](https://github.com/MolfarWav/Molfar.Vertep/blob/main/CHANGELOG.md) for details.
