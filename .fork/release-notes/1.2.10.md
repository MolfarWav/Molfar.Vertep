# 🔐 Molfar Vertep 1.2.10

Molfar no longer sits for ten minutes waiting for a button that is not there, the "send now" arrow is visible from the start of a run, and a failed Chub reply says why.

### 🔐 Approval cards no longer get lost
When Molfar changes an app's protected files (the UI code), it asks first with a card: **Allow** or **Don't allow**. A model that asked to edit the same app twice at once (several edits in one step is common with local models) used to open two questions; the page has room for one card, so the other question stayed unanswered with no buttons and Molfar looked frozen until the engine gave up after exactly 10 minutes (#76).

Now:
- questions of one chat come **one at a time**; the second edit in the same app uses your answer to the first instead of asking again;
- the page **asks the engine for a waiting card** when the connection comes back, when you return to the tab, and every few seconds while a run goes on, so a card event lost on the way (a dropped connection, a tab in the background, a page reload) shows up on its own;
- a question that does time out **closes its card** instead of leaving a stale one that fails with "no pending question" (a part of #73).

Not in this release: a "YOLO" mode that skips the questions. The questions protect the code you did not ask to change; whether to offer a switch, and how wide it should be, is a decision for a later release.

### 🔔 Molfar's question pops up wherever you are
If Molfar asks you something while another tab is open (you are in Roleplay, say, and left the agent running), a card appears at the right edge: the question, and **Open Molfar**, which takes you to the card to answer. The × hides that one question; a new question shows again. It does not appear when the agent is on screen (its tab, or the split view). The answer is still given on the agent page.

A related fix: two edits to the same protected file made at once used to lose the first (the second was computed before the question and overwrote it). After your answer the second edit is now redone on the file as the first left it.

### ➡️ The "send now" arrow is always there during a run
While Molfar works you can send a correction (the arrow next to Stop). Until now it appeared only after you typed, so many people never found it. It now shows for the whole run, dimmed while the box is empty (hover for what it does), and turns on as you type (#71).

## 🛠️ Fixes
- **Chub (Soji) errors are readable** (#59). When Chub answers with an error text and then the end marker (`upstream timed out. Server may be overloaded, or your input too large or malformed`), the reply fails with Chub's text instead of an empty `...`. The timeout itself is Chub's; it is not something the engine can fix. Custom connections also stop sending OpenAI's `store` field to other hosts, the one body field Marinara and plain curl do not send.
- **A reload of an app page can be explained** (#24). When the page reloads because the builder rebuilt the app, the cause (which files, or the update) goes to the browser console and into the recent errors a bug report carries. If Roleplay ever refreshes by itself, the report now says why.
