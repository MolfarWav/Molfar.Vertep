# 🧬 Molfar Vertep 1.7.3

Apps open faster after a change, there is a way to clean up pictures nothing uses, and Molfar can load an app's rules only when it touches the app. Roleplay 4.77.0 rides along as an app update. **Order:** get this engine release and restart, then open Updates and press Update on Roleplay.

## ⚡ Apps reopen faster after a change (#181)
Roleplay used to rebuild all of its modules when you opened it after any change made while it was closed: an update, a sync pull, an edit by Molfar, even a note in `docs/`. Now the build remembers what it built. Notes, tests, scripts and top-level markdown files no longer count as app code, and a change to a few files updates only those modules. On a 353-file Roleplay: after a docs edit 24 s to 4 s, one source file 37 s to 11 s, ten files 25 s to 6 s. A full build from nothing is unchanged (about 40 s). The first open after this update does one full build, because the old build has nothing saved to compare with. Anything unusual (a new package, `package.json`, a changed `public/` file) still builds everything.

## 🧹 Clean up unused pictures (#171)
Settings > **Storage**: finds the pictures in the asset store that no file of yours mentions (cards, chats, notes, apps' data) and that were stored more than 7 days ago, and moves them to a trash. The trash keeps them for 30 days; restore one or all, or empty it. The server checks again at the moment you press the button, and anything that gets referenced meanwhile is put back. If a file could not be read, nothing is moved. Pictures are shared between your devices by sync and a cleanup is a deletion for it, so the trash lives only on the device that cleaned: restore there.

## 🪶 Molfar: the app's rules on first touch (#174)
A switch in the Memory and skills dialog: "Load the active app's rules when Molfar first touches the app". Off by default. When on, the active app's `AGENTS.md` and `data/README.md` (about 5.6k tokens, half of a plain chat's system prompt) are not sent on every call; they come with the first result that touches `apps/<id>/`, and a first call that would change the app is held back once and answered with the rules, so Molfar reads them before changing anything. A chat inside the app's own project keeps them in the prompt. Try the same task with the switch on and off and compare.

## 🗺️ Roleplay 4.77.0
- **Sprites in outfits, and per character (#170, #169).** Add a whole pack at once: a dialog reads each file name into character, outfit and emotion (`Aria_joy_dress.png`), shows what would replace what, and a progress card with Cancel follows. A card holds several outfits per emotion; a Narrator card has a set per voice, and the chat shows the sprite of the voice that speaks last, with an outfit switch in the sprite panel. Old cards are unchanged.
- **Tags as folders in Characters (#151).** Mark a tag "folder" in the tag manager and it shows as a chip above the list with a count; a character can be in several.
- **World: choose the model that builds a world (#164).** A "Build model" row in World settings; "Pick another model" now leads there.
- **Litopys: cause and effect between facts (#178).** A fact can name its cause; when it is recalled, its cause follows when it fits, and the Library shows "because: ...".
- **Fix: importing a preset with hundreds of regex scripts** sat on "Checking 30%" for minutes. A preset with 223 scripts now imports in about 7 seconds.

## How to get it
From source: `git pull && bun install && (cd client-agent && bun install) && bun run build:client`, then restart, then Update on Roleplay in Updates. Downloads and the Android APK are on this release page. See [CHANGELOG.md](https://github.com/MolfarWav/Molfar.Vertep/blob/main/CHANGELOG.md) for details.
