# 🏠 Molfar Vertep 1.16.3

A small release: file names with a long dash or Cyrillic download again, the update check says why it failed, and plugins that read a lot get more time on a slow phone. It carries two app updates: **Roleplay 4.115.0** and **Social 0.15.0**. **Order:** get this engine release and restart, then press Update on **Roleplay** and **Social** in Updates.

## 📁 Files with a long dash or Cyrillic in the name download again
A picture or file whose name held a character outside plain Latin (a long dash, Cyrillic, an accent) made the engine answer with an error instead of the file, over and over in the log. The name is now sent in the form browsers understand, and shows as you wrote it. This covers pictures, workspace files and project exports.

## 🔁 Roleplay 4.115.0: an update no longer wipes your other device's vectors
Roleplay 4.112.0 moved the "matching by meaning" vectors into each device's own cache and deleted the old synced files. That deletion travelled through the sync, so a device that had not updated yet lost its vectors and had to embed everything again. Now the old files are copied and left where they are. A device that already lost them needs one more embedding pass; nothing else is lost.
- **A reply from someone's view no longer knows what that character never saw.** "Continue from someone's view" now also tells the memory which character is speaking, so the recent messages from scenes without them are replaced by a short "was not here" line, in any chat, a narrator card included. It reads the direction the menu writes; a hand-typed "OOC: Pov Alice" is not recognised.
- **Dashboard: more kinds of kiss.** New events for a tender kiss (forehead, cheek, hand) and a hug raise no arousal; only a romantic kiss does, and a gentle touch gives less. The sensor is told that events are what your character does, and that a character cheating on or lying to yours does not lower that character's trust in you. The Dashboard's guide page says whose feeling each number is. A fuller review of the whole event table is planned (#394).
- **The Scenes card reads clearly:** "58 of 59 messages are already in scenes (the chapters below); 1 not yet".
- **More time on a slow phone:** the engine plugin may take up to 30 s to answer a read, so a long chat in a big library no longer times out at the start (needs this engine release).

## 💬 Social 0.15.0: `@` in a forum reply
Type `@` in the reply box and a popup list of names opens over the box: the topic's authors first, then every character. Arrow keys and Enter, or a tap, put `@Name` in. A character written as `@Name` answers you first, even if it has not posted in the topic and even when you quote someone else's post. The name must end where it is written (`@Al` is not `@Alice`).

## 🛠️ Fixes
- The Updates dialog no longer shows a bare "internal error" when an app's update check fails before it reaches the repository: the engine logs the reason and shows an error code (#390; the cause on the reporter's phone is still unknown).

## Other changes
- The engine accepts `limits.executionMs` (10 to 30 s) in a plugin's manifest for read routes of trusted plugins; the default stays 10 s.
- The sensor prompt of the Dashboard has a new default; a saved copy of the previous default follows it as before.

## Known limits
- Not tried on a real synced pair of devices, on a real model for the Dashboard changes, or on a phone for the 30 s limit.
- The popup `@` list was checked in the design preview (dark and light, desktop and 390 px), not on the live forum. Names in posts are not highlighted yet.
- The guide translations of the three changed pages were made by a cheap model without a native read.

## How to get it
From source: `git pull && bun install && (cd client-agent && bun install) && bun run build:client`, then restart. Downloads and the Android APK are on this release page. Apps: Updates > Roleplay > Update, then Social. See [CHANGELOG.md](https://github.com/MolfarWav/Molfar.Vertep/blob/main/CHANGELOG.md).
