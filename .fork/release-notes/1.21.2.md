# 🧭 Molfar Vertep 1.21.2

A small engine release: **an open app catches up on edits it missed**, and **sync asks once for a long chat**. It goes out together with **Roleplay 4.164.0**, where long chats stop failing at the 4 MB limit, turns of a long chat read far less, and memories of earlier chats come from the chat itself.

## 🔄 An open app no longer misses an edit
If an app was edited while its page had lost the connection to the engine (Vertep in the background on Android, a short network drop), the page never heard of that edit. The next edit then built only its own file, the missed change stayed out, and the app still counted as up to date: only **Rebuild** showed it.
- When the connection comes back, and when you return to the page, the app now asks the engine what changed and builds it.
- Each later build also takes in every file that differs from the last build, not only the file of the newest edit.
- A build that still missed something is no longer recorded as current, so the next open builds the rest.

## 🔁 Sync asks once for a long chat
Roleplay 4.164.0 keeps a long chat's older messages in a folder beside the chat. When a sync between two devices found a conflict, it asked about every one of those files separately. Answering "mine" for the chat and "theirs" for one of its parts could leave a chat that no longer fits together. Now the chat and its parts are one question.

## 📦 What arrives through app updates: Roleplay 4.164.0
Press **Update** in the Updates dialog to get it.
- **Long chats keep working past 4 MB.** A long chat (650 messages with reasoning on) failed every send with "content too large (4MB)". Now a chat of more than 200 messages keeps its older messages in parts of about 100. A send rewrites only the newest messages, and the chosen text of a message is stored once, so a 3.55 MB chat takes about 2 MB.
- **A turn of a long chat reads much less.** The prompt and the plugins read the newest messages and a light index of the older ones; an old message is read only when something needs its text.
- **The page loads a long chat by pages.** Opening a chat and every refresh after a reply bring the newest messages, not the whole transcript. "Load earlier messages" fetches the page before it. Find, export, bookmarks and translating the whole chat load the rest first.
- **Word-for-word memories of earlier chats work for long chats too.** The memory of an archived chat no longer keeps a second copy of its whole text. A reply reads the passage it uses straight from the chat, and a chat too long for that copy used to have no such memories at all; now it has them.
- **Also find old chapters by meaning** (experimental, off by default): when several passages of the chapter it opens share a word with the scene, the one closest in meaning is taken. The Memory view marks it "closest by meaning of N".
- **Update every device.** An older Roleplay on another device sees only the newest messages of a long chat, and it cannot show a swipe whose text is stored once. If you go back to an older version, run `bun scripts/chat-join.ts <data dir>` first. If an older version deletes a long chat, it leaves the chat's `chats/<id>.parts/` folder behind; delete that folder by hand.

Thanks to LeviTheWeasel for the long-chat storage and paging (Roleplay PRs 217 to 219).
