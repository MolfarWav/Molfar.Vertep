# 🏠 Molfar Vertep 1.16.2

A small release: the Stop button in the Roleplay chat now really stops a reply, plus three additions to Roleplay (4.114.0). **Order:** get this engine release and restart, then press Update on **Roleplay** (4.114.0) in Updates.

## 🛑 Stop in the chat works the whole time
Before, a Stop pressed right after Send did nothing: between Send and the moment the model is asked, the engine builds the prompt (a few seconds, longer with a big memory), and a Stop in that gap was lost, so the reply was written anyway. Now the engine remembers that Stop, and the model is never called for that reply. Stopping a regenerate in that gap works the same way.
- **Engine (this release):** the Stop is kept for the chat's running request and applied the moment the model request would open.
- **Roleplay 4.114.0:** a Stop in the middle of a reply to a message you sent now keeps the half-written text (it was lost before, because your message had already been saved), and no longer ends in a red "model failed" message.
- If you press Stop while the prompt is still being built, your message stays in the chat with no reply: send again or write a new one.

## 🎭 Roleplay 4.114.0
- **Continue from someone's view.** When the persona and the other characters have gone different ways, the "+" menu in the chat has **Continue from someone's view**: pick a character (the Dashboard's people, the ones in the scene first) and the next reply follows that character. It sends a stage direction alone, so nothing is said in the story and no turn of yours is added. "Someone else..." types the direction into the box for you.
- **Dashboard: "Not in the scene".** A weak model sometimes puts a character the prose only mentions into the scene. The Manage menu in a person's header now has **Not in the scene**: the character leaves the present list, stays known with their notes, and the Dashboard does not put them back unless they speak. The toast has Undo. "Remove from the Dashboard" is unchanged: it forgets the name everywhere.
- **A new built-in preset, Vertep Medium.** Vertep Middle with a Braille-spaces module at the top and its three regex scripts. An update adds it (read-only, like the other built-ins: duplicate it to edit).
- **World DM:** if "New deck" gets fewer than 8 events back from the model, a warning says the deck came back short, so you can build it again.

## Other changes
- Handbook fixes in the docs: the entity registry says holders are names, `COUPLINGS.md` explains the two kinds of dice, `.fork/RELEASE.md` matches what the code does.
- A test now records that imported plugins do not run the memory plugins' insert ceilings (a known gap, not changed here: it needs a decision first).

## Known limits
- Stop pressed in the prompt-building gap while some other long chat request is the only one running can be applied to the next send; rare, and it ends with that request.
- Not tried with a real provider, on a phone, or in group chats. The new guide strings are translated by a cheap model without a native read.
- The text saved after a Stop in the middle of a reply may start a word or two late (open issue #383, older than this release).

## How to get it
From source: `git pull && bun install && (cd client-agent && bun install) && bun run build:client`, then restart. Downloads and the Android APK are on this release page. Apps: Updates > Roleplay > Update. See [CHANGELOG.md](https://github.com/MolfarWav/Molfar.Vertep/blob/main/CHANGELOG.md).
