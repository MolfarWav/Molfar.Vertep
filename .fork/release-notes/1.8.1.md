# 🧬 Molfar Vertep 1.8.1

A small release. When a model provider cuts a reply short, the error now says why. It ships together with Roleplay 4.78.1 as an app update. **Order:** get this engine release and restart, then open Updates and press Update on Roleplay.

## 🔎 Why a reply was cut short
- A host that ends a stream with `finish_reason: "error"` used to show only "Provider finish_reason: error". The error now carries what the host said: OpenRouter's `native_finish_reason` (for Gemini, for example SAFETY or PROHIBITED_CONTENT), an error on the choice, or the chunk's other fields when a host puts the reason somewhere new. The whole chunk also goes to the engine log (`stream ended with finish_reason "error"`).
- Replies from the built-in agent are not covered yet; a reply that is cut mid-way is not retried.

## 🧑‍🤝‍🧑 Roleplay 4.78.1 (app update)
- **One character is no longer listed twice** on the Dashboard and in the Litopys when the card's Soul is keyed by the first name ("Sina") and the card is called "Sina Rose". A chat that already shows both lists one; the next reply drops the other from its saved state.
- **A button on the character card takes a character off the Dashboard** (asks first, not offered for the only character), for a name the sensor made up or doubled. The sensor does not bring it back.

## How to get it
From source: `git pull && bun install && (cd client-agent && bun install) && bun run build:client`, then restart, then Update on Roleplay in Updates. Downloads and the Android APK are on this release page. See [CHANGELOG.md](https://github.com/MolfarWav/Molfar.Vertep/blob/main/CHANGELOG.md) for details.
