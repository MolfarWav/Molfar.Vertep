# 🔧 Molfar Vertep 1.6.1

A patch release: a fix for big imported libraries, no more broken `:batch` models, and OpenRouter service tiers. Roleplay 4.73.1 rides with it as an app update. **Order:** get this engine release and restart, then open Updates and press Update on Roleplay. If Roleplay does not start at all, Updates is in the shell and still works: update Roleplay from there first.

### 🧯 A big imported library starts again (#159)
After a mass import from SillyTavern (about a thousand characters and more) Roleplay could stop opening: "Can't reach the Molfar Vertep engine ... GET /bootstrap failed: out of memory", and imports running at the same time failed with "worker exited". The start-up list sent every lorebook whole, and a SillyTavern import brings a book of about 100 KB per character, so the plugin ran out of memory. Now the list carries a short summary of each book (name, switches, linked cards, number of entries, a token estimate) and the whole book is loaded when you open it, the same way characters have worked since #46. Exporting a card loads its own book first, so nothing leaves without it. Sending a message also used to read and parse every book file of the library; it now reads only the books that apply. Your files on disk do not change. On a test library of 1,300 characters with 1,300 books the start-up list went from over the memory limit to 1.9 MB.
If some of your imports failed, run them again after the update.

### 🚫 Models that end in :batch are gone from the lists (#160)
OpenRouter and Nous list a `:batch` twin of many models (for example `google/gemini-4-argon:batch`). Only the provider's batch service serves them; a normal reply to one failed with "404 ... cannot be used with the chat/completions endpoint". They are no longer offered, from any provider. If you had already picked one, choose the model without `:batch` (for the World builder see #164, which still has no picker for the build model).

### 🚦 OpenRouter service tiers (#161)
Settings > Models > a model's panel has a new "Service tier" field for OpenRouter models, in every block (Chat, Plugins, Molfar, one plugin). It sends `service_tier` with the request:
- **Default**: OpenRouter's normal speed and price.
- **Flex**: cheaper, slower; the reply may wait in a queue.
- **Priority**: faster, costs more.
- **Ultrafast**: the fastest lane, costs the most.

OpenRouter bills by the lane that served the request, so the cost Molfar Vertep shows (from the catalog price) can differ from the real one. OpenRouter's Claude models do not take it here (they use a different wire), and the field says so. It is switched off until you tick it. `:nitro` and `:floor` variants are not part of this.
Not checked against a live OpenRouter account yet: tell us if a tier is refused.

## How to get it
From source: `git pull && bun install && (cd client-agent && bun install) && bun run build:client`, then restart, then Update on Roleplay in Updates. Downloads and the Android APK are on this release page. See [CHANGELOG.md](https://github.com/MolfarWav/Molfar.Vertep/blob/main/CHANGELOG.md) for details.
