# 🧹 Molfar Vertep 1.2.12

A fuller SillyTavern preset import with a report, pictures in greetings, wires and attachments that behave, and two bug fixes. Almost all of it is Roleplay 4.59.0, an app update.

### 📥 SillyTavern presets come over with their structure (Roleplay 4.59.0)
A SillyTavern preset has no groups or choices: authors fake them with header prompts ("━ Point-of-View", "=Pick one POV ====", "PICK: AGENCY") followed by toggles. The import used to flatten all of that into one long list (#57). Now:
- Those blocks become section groups and **Choices** with options, and a hint under an option where the preset had a comment for it. One option on, or "pick one" in the header, makes a single choice (with a **None** option when nothing is on); several on makes a multi choice.
- A prompt made only of `{{setvar::name::value}}` lines (the "Prompt Variables" prompt of big presets) becomes text variables you can edit.
- Prompts the file does not use go to the prompt library, off. The preset keeps the file's name and the author and licence the file states.
- The preset's own regex scripts come over bound to the preset. A script whose pattern cannot compile is left out and named.
- `{{noop}}`, `{{setglobalvar}}` and the other global-variable macros work here, and presets that pick options in macro code (`{{.x = v}}`) no longer leak that code into the prompt.
- Also read: unlocked context, reasoning effort words (min, max, auto), "show thoughts" off.
- **A report** opens after every import (Presets or Settings → Import): what came over, what was approximated (including where it guessed pick-one or pick-several, which you can flip in the preset's Choices) and what was left out (macros this app does not expand, the summary block whose job Litopys does, settings with no equivalent). Marinara presets get one too.
- A Marinara **regex file** imports now; it was refused as "no valid regex scripts".

- Importing the same preset again gives it a numbered name ("name (2)") instead of a second one with the same name, and a Marinara preset that carries regex scripts keeps them, bound to the preset.

### 📎 Unsent attachments survive a reload (Roleplay 4.59.0)
A file you attach but have not sent used to vanish when the page reloaded or the app rebuilt (#31). It is now kept for its chat (up to eight), and a file attached in one chat no longer rides along into another.

### 🕸️ Canvas wires (Roleplay 4.59.0)
A wire to a card level with or above its source goes out to the side, round both cards, instead of running through them (#41).

- The Chat links board is saved in the app settings, so it is there on every open and follows you to another device (it lived in one browser before). While dragging a wire, the label "Already connected" no longer shows over every valid card.

### 🖼️ Pictures in a greeting (Roleplay 4.59.0)
A picture a card writes in its text (`![alt](https://…)` in a greeting) showed as a broken-image icon (#84). It now loads through the engine's image proxy, the way the Store already did. The proxy serves the card sites the Roleplay plugins list (Cloudflare Images, JannyAI, Chub and the like); a picture on another host, or a dead link, shows its alt text as a link. Found, fixed and sent in by goosebillis through Molfar's "send the fix" button: thank you.

### 🧵 Dashboard threads (Roleplay 4.59.0)
A thread the sensor resolved no longer comes back as a new open one when the model also lists it as open (#81). The sensor prompt now says not to.

### 🛠️ Rebuilds after an update
After an app update another tab or device could leave an open tab's builder holding a files list that no longer matched what was built, which showed as "keeps dev/deps-… which dist does not have" and one automatic retry (#26). The builder now checks before each build and starts fresh when another build has moved on. The cause is inferred from the report, not reproduced.

## Other changes
- The Z.ai item (#49) is closed: the details needed to find a cause never came.
- pi stays at 1.2.0.
