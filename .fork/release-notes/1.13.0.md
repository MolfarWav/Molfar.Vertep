# 🔌 Molfar Vertep 1.13.0

Apps can now read each other with your say, tell you that something is waiting, and follow the shell's colours. This is the engine side of the **Social** app (messenger and forum): its Roleplay import needs this release. Roleplay itself is unchanged. **Order:** get this engine release and restart, then update Social in the Store or in Updates.

## 🔐 Apps can read other apps, with your say
- An app may list files of another app it wants to read, with a reason. The first time such an app opens, the shell asks once: **"Allow Social to read your Roleplay data?"** It shows the reason and the exact file patterns. Allow, Don't allow, or Decide later (it asks again).
- Your answer is kept outside the workspace, so an app cannot grant itself access. It covers only the files that were shown: an update that asks for more asks you again. It is forgotten when either app is removed. You can change it any time on the app's page on Home, under **Access to other apps**.
- What an allowed app gets is read only: the declared files, 2 MB per file, no links followed, no file paths in errors, no way to write or delete anything.

## 🔔 Apps can tell you something is waiting
- An official app can put a number on its tab in the shell and show a short message in the bottom right corner (a system notification when the window is not in front; nothing while you look at that app). One message per app every 5 seconds.
- A switch per app on its page on Home, **Notifications from this app**, on by default. The browser's permission and the Settings switch for system notifications still decide the system notification.

## 🎨 Apps can follow the shell's colours
- Every app frame is told the shell's theme (dark or light, and the colours of a custom theme) when it opens and when you change it, so an app can repaint with the shell. It is data only; it gives an app no access to anything.

## Other changes
- Guide: the "Apps" page covers reading other apps. The new shell strings are in all 14 locales.
- New shell-only routes `GET /v1/apps/:id/reads` and `PUT /v1/apps/:id/reads/:peer`; app frames cannot call them.

## Known limits
- Translations of the new strings and of the guide page were made by a cheap model and not read by a native speaker.
- System notifications themselves were not tried (a headless browser has no permission); the popup and the tab count were.
- Social's import from Roleplay was tried with a mock model and a stub Roleplay app, not with a real model yet.

## How to get it
From source: `git pull && bun install && (cd client-agent && bun install) && bun run build:client`, then restart. Downloads and the Android APK are on this release page. See [CHANGELOG.md](https://github.com/MolfarWav/Molfar.Vertep/blob/main/CHANGELOG.md) for details.
