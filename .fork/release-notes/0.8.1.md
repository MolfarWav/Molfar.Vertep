# 🎭 Molfar Vertep 0.8.1

The story now moves on its own when you ask it to, the chat reads like a book, and the Android app starts on Android 11 to 13. Your apps, chats and settings are kept.

## ✨ What's new

### 🌬️ "Story, move" (Roleplay 4.24.0, through app updates)
Open **Updates** in the top bar to install Roleplay 4.24.0. A new button left of **Send** makes the next reply move the story on its own instead of only reacting to you: the world or another character acts, pulling on the dashboard's open story threads. Press it with an empty message box and the reply comes at once; with text typed, the push rides your own message. The arrow beside it lets you pick one thread to push. A line above the message box shows what is armed and takes it back with ×. The push goes into that one request to the model only: it is never saved in the chat or shown as a message. Its wording can be changed in the dashboard plugin's settings.

### 📖 A new chat look
Messages read like a book page: no boxes, a serif typeface with room between the lines (a font or spacing you chose yourself is kept). Characters stand in an arched portrait with an embroidered band; your own turns are set off to the right. When the dashboard sees the story move to a new place, a heading with the place and the time of day appears between the embroidered bands. **Edit**, **Copy**, **Regenerate** and **More** show under a message when you point at it, and always on phones; **More** is grouped into Message, Story and Delete. The model, time, tokens and cost of a reply appear on hover, and the chat's model, spend and context use moved into an **i** button in the header, which no longer gets cut off on narrow windows. The display mode, avatar shape and message tint settings are gone: there is one look.

### 🖼️ From the chat to the card
Click a character's portrait, in a message or in the chat header, for **Card**, **Soul**, **Dashboard** and **View portrait**. In a group chat it opens the character who spoke, not the group card. Phones get the portrait in the chat bar too.

### ⚡ Dashboard fast mode
For strong story models: choose **Fast: inside the story reply** in the dashboard's settings (Sensor). The story model then writes the dashboard's state report at the end of its own reply, so there is no separate sensor call per turn. The report is cut out before you see or save the reply, also while it streams. It adds about 2,500 tokens to every request (the settings show the number for your setup), and when a reply leaves the report out or it cannot be read, the usual sensor runs. The separate sensor stays the default.

### 📱 The Android app starts
The app now starts on Android 11 to 13, where **Start** did nothing before: the engine made system calls these Android versions do not allow apps, and Android stopped it at once. A small library loaded with the engine answers such calls with "not supported", so it takes its fallbacks; installing an app's packages no longer takes the engine down either. If a start ever fails, the reason stays on screen and **Logs** shows what the launcher did. The app is called Molfar Vertep, has the Vertep logo and Ukrainian texts, and has its own package id: it installs as a new app beside an old Chrysalis one (export a backup in the old app and import it in the new one).

### 🔆 The Vertep logo
The Vertep sun replaces the old logo on the login and start screens, in browser tabs, on the launcher's desktop shortcut and as the Android app icon.

## 🛠️ Fixes
- **The dashboard reaches the story model again.** Since an app update or on a fresh install, the dashboard's insert into replies (how the characters are right now) silently never reached the model: the engine skipped imported apps' prompt hooks. "Story, move" and fast mode depend on the same fix.
- **Subscription sign-ins work in the downloads and the Android app** (Claude Pro/Max, ChatGPT Plus/Pro, GitHub Copilot, OpenRouter, Kimi, SuperGrok, Radius). They failed with "Cannot find module"; running from source was not affected.
- **Molfar no longer stops mid-sentence** when the provider drops a tool call it could not read: the half-written reply stays, Molfar is asked once to repeat the call, and then to answer or ask its questions as plain text.
- **No more echoed name** at the start of replies ("Aria: …"): new replies lose it when saved, also in group turns; older ones hide it on screen.

## Other changes
- Litopys adds its lore to replies only when you switch on **Insert into the prompt** in its settings (off by default; it never actually reached the prompt before because of the hooks bug above).
- App builds and package installs are written to the engine log, so a failing build can be traced.
- The Android download is now named `Molfar-Vertep-<version>-android-arm64.apk`; the other downloads keep their names.

## ⬇️ How to get it
- **Launcher users:** run `Molfar-Vertep.bat` and answer **Y** to "Update to release v0.8.1". Then open **Updates** in the top bar for Roleplay 4.24.0.
- **Running from source otherwise:** pull the tag `v0.8.1`.
- **Downloads** below: `Chrysalis-0.8.1-<system>` for desktops (names kept so self-update keeps working) and `Molfar-Vertep-0.8.1-android-arm64.apk` for Android 9 and newer. The APK is debug-signed: a later APK cannot update it in place, install it fresh and keep a backup.
- **Docker:** `ghcr.io/molfarwav/molfar-vertep:v0.8.1` or `:latest`.
