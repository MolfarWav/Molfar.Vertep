# 🧬 Molfar Vertep 1.9.0

A big Roleplay release: personas get a full rework, the World book fills itself from the story, and the Dashboard stops forgetting what characters wear. Almost all of it arrives as Roleplay app updates (4.79.0 and 4.79.1); the engine itself changes its version and one built-in Molfar skill. **Order:** get this engine release and restart, then open Updates and press Update on Roleplay.

## 🎭 Personas, a new look (Roleplay 4.79.0, #186)
- **An overview you can scan.** Each persona is a card with a portrait, a one-line summary, tags, chats, tokens and how much of the profile is filled. A preview panel sits on the right (a bottom sheet on a phone). Search and four sorts: Recent, Name, Most used, Tokens.
- **Tags and folders**, like Characters. Folders are made from persona tags marked "folder", and a card can be dragged onto one. Select mode moves several personas to a folder, tags, exports or deletes them. The "N chats" link opens Chats showing only that persona's chats.
- **A persona's own page.** A banner with the portrait, name, pronouns, a one-line title and tags edited in place, then tabs: Core, Profile, Bindings, Lorebooks, Memory, Colours, Gallery. Profile has "Model for this card's tasks" like a character, Fill empty, Structure it and Edit answers. "Generate image" builds a portrait prompt from the Appearance fields (you edit it before sending), puts the result in the Gallery, and "Use as portrait" sets it. On a phone the page is a list of sections, each opening on its own page.
- **New persona is a chooser:** write it yourself, answer a short interview, or start from a file. The interview asks for a few words (and optionally a picture), a model proposes three drafts, you pick one, answer two questions and choose how detailed it is (Quick sketch, Full portrait, Deep dive). A text, Markdown or JSON file becomes the description of a new persona and Structure it sorts it into the profile fields; a file of personas imports as before.
- **Small things:** the preset list marks the default preset with a star, and the Dashboard's "Leads" line is readable.

## 🌍 The World book fills itself (Roleplay 4.79.1, #185)
- A chat twelve turns into a school story had no records at all, because the DM model judged a changing room and a corridor not worth one. Now code reads the places the scene tracker named along the chat and the things it saw lying around (also what was left behind when the story moved on), takes away what the book already has, and a small records-only run offers the rest to the DM model by name.
- It runs after a reply, only when there is something new, once per name (what the model declines is not asked again). **DM Off now means no events and no dice**, while the book keeps filling and "World · here" keeps going into the reply prompt. A chat that never had a world (an assistant card) is left alone.

## 👗 The Dashboard keeps clothes, held things and positions (Roleplay 4.79.1, #185)
- **Outfit details no longer drift.** The sensor used to rewrite what a character wears, so "pink soft knit cardigan" became "a cardigan" and colours changed. Now the sensor reports only changes (add and remove lists for outfit and held things, a place for each character and for you, and what lies around) and the plugin keeps the lists. An item is matched by its words; removing something that is not listed changes nothing; a worn thing that is put down moves to the scene objects with where it lies. Positions and objects start over when the story moves to another place.
- **The outfit stays in the prompt** on turns that do not mention it. A character with no clothes on record is asked to be described in the next reply; the sensor picks the description up without an extra model call.
- **A switch in Dashboard settings**, "Remind the model where everyone stands and what they wear" (on by default, about 40 to 100 tokens). The block is also visible in the prompt inspector. The sensor prompt changed, so the previous default counts as the default; a plain-text outfit from an older custom sensor prompt still works.
- Not yet checked on a real model: how well a weak model fills the new fields, and a phone-width look at the switch.

## 🧭 Molfar's design rules
- The built-in `ux-review` skill, which Molfar reads before it builds or changes an interface, now sets a design bar (practical, native, designed, client-first), asks for a short plan with variants before the code, says how a fold must look (a visible header with a summary when it is closed, never a fold inside a fold), asks that the one button that commits something stands out, and sets 12 px as the smallest text. A workspace copy of the same name still replaces it.

## How to get it
From source: `git pull && bun install && (cd client-agent && bun install) && bun run build:client`, then restart, then Update on Roleplay in Updates. Downloads and the Android APK are on this release page. See [CHANGELOG.md](https://github.com/MolfarWav/Molfar.Vertep/blob/main/CHANGELOG.md) for details.
