# 🧬 Molfar Vertep 1.7.1

The program stops being called `chrysalis`. From this release the file you start is `molfar-vertep` (`molfar-vertep.exe` on Windows), and every other internal name moves with it. Roleplay 4.75.0 rides along as an app update. **Order:** get this engine release and restart, then open Updates and press Update on Roleplay.

## ⚠️ Read this first if you run a downloaded copy
- **Windows:** after the update the program is `molfar-vertep.exe`. A desktop shortcut or a pin that points at `chrysalis.exe` stops working: start `molfar-vertep.exe` from the same folder and make a new shortcut. The old file stays beside it as `chrysalis.exe.old` for one rollback.
- **A copy older than 1.2.3 cannot update itself across this.** Download the new archive once from this page. Copies on 1.2.3 or newer update as usual.
- The terminal command is `molfar-vertep` now. The first start of the new version puts it on your PATH and removes the old `chrysalis` link. Scripts that call `chrysalis` need the new name.
- Running from source (`Molfar-Vertep.bat`) changes nothing for you.

## 🏷️ The rename (#66)
Done for everything internal, and nothing an old install left behind is lost:
- **Folder and log:** the app-data folder is renamed on the first start (`%LOCALAPPDATA%\MolfarVertep`, `~/Library/Application Support/MolfarVertep`, `~/.local/share/molfar-vertep`) with your config, accounts and workspaces inside. If something holds a file in the old folder and the move fails, the old folder is simply used and the move is tried again next start. `logs/chrysalis.log` becomes `logs/molfar-vertep.log`.
- **Settings by environment:** `MOLFAR_VERTEP_*` is read first, `CHRYSALIS_*` still works.
- **Signed in:** the session cookie has a new name; a browser signed in under the old one stays signed in. Theme, language, open tabs and composer drafts move to new browser keys on the first load.
- **Docker:** the volume is `/molfar-vertep`. A setup that still mounts `/chrysalis` keeps working and prints a note to move the mount.
- **Android:** inside the app only (library, Java package, theme). The app id and its updates are unchanged. Not built on a phone yet.
- **Apps:** `window.molfarShell`, `window.molfarStorage`, the `molfar:*` events and the `x-molfar-app` header are the new names. The old names keep working, so installed apps need nothing; an app's saved browser storage moves to the new key on its next save.
Not checked: an update from a real 1.7.0 download (the update code and its tests cover the rename, and the new program was built, started and smoke-tested), and the Android build. Tell us if an update from 1.7.0 does not come up.

## 🗺️ Roleplay 4.75.0
- **Named boards in Chat links (#108).** A button beside Tidy lists your boards: start a new empty board, switch, rename, delete. A board remembers which chats sit on it and where; the links between chats are shared by every board, so a new board loses nothing. An install with one board keeps it as "Main board".
- **Marinara imports (#96).** Marinara character and lorebook exports unwrap and import with keywords, order and position intact; a depth prompt from SillyTavern or Marinara becomes the card's depth prompt.
- **Import progress (#116).** The Regex page and the card Memory import use the shared progress card; a failed file is listed with its reason instead of also raising a toast.
- **Phone fixes (#146).** A 44 px Close button on dialogs, translated labels, bigger switches on a phone, and a few Forge warnings and naming fixes.

## How to get it
From source: `git pull && bun install && (cd client-agent && bun install) && bun run build:client`, then restart, then Update on Roleplay in Updates. Downloads and the Android APK are on this release page. See [CHANGELOG.md](https://github.com/MolfarWav/Molfar.Vertep/blob/main/CHANGELOG.md) for details.
