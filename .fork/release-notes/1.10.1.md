# 🧬 Molfar Vertep 1.10.1

A small engine release: an app that **never builds** now tells you why, instead of sitting on "Building the app" for ever. There is no app update in it.

## 🛠️ The builder no longer waits for ever (#224)
- Apps are built inside your browser, in a hidden frame. If the browser never starts that frame, the tab used to say "Building the app" with no error, no CPU use and no log. The usual cause is a **reverse proxy** in front of the engine that does not pass the `Host` header unchanged and `X-Forwarded-Proto: https` for HTTPS (the frame's security policy is built from them); a browser extension that blocks frames can do it too.
- The frame now has **30 seconds** to start, esbuild 2 minutes more. Then the tab shows an error that names the likely cause and what to look for in the browser console ("Content Security Policy", "Refused to frame"). Slow phones are not hit: the download of the builder is not counted.
- A proxy that rewrites `Host` makes the engine **refuse every write**, and the tab showed "Another open tab is building this app" for ever. It now shows the engine's own message ("cross-origin write refused") with the advice to pass `Host` unchanged.
- Nothing changes when the address and the proxy are right: the same app builds in the same time.

## How to get it
From source: `git pull && bun install && (cd client-agent && bun install) && bun run build:client`, then restart. Downloads and the Android APK are on this release page. See [CHANGELOG.md](https://github.com/MolfarWav/Molfar.Vertep/blob/main/CHANGELOG.md) for details.
