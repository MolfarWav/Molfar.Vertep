# 🧭 Molfar Vertep 1.21.1

A small engine release: **updating an app no longer throws away its build**, so the first open after a Roleplay update is quick, **a running build is visible** (also on a phone), and **an app can hand a short name to the app it opens**.

## ⚡ The first open after an app update is no longer a cold build
Every app update used to delete the app's built files, so the first open after it bundled every package and built every module again on your device: about 22 MB and 3 to 10 minutes on a phone, where a manual Rebuild of the same code took half a minute. The built files now stay. After an update the app rebuilds only the files that changed and keeps the packages it already bundled. A full build still happens when the app's packages changed, or its `index.html` or `public/` folder.
- The speed-up starts with the first update you install **after** this engine release: that update is the first one that keeps the build.
- If a build fails after an update, the app keeps showing its previous version, like after any failed edit.

## 🕐 You can see that an app is building
On a phone nothing showed a build once the app was open, and a long one looked like a hang.
- A thin line above the app says **"Building the app… 1:23"** while a build runs, also after you press Rebuild. The full-screen wait shows the clock too, says which part is going ("Building app code…", "Bundling packages…") and, after 15 seconds, that a build can take a few minutes, longer on a phone, and to keep the page open.
- **Rebuild** (the toolbar button, and the entry in the account menu on a phone) turns into a greyed "Building… 1:23" and cannot be pressed twice.
- **Settings > Developer** now says what each app's build is: "Built and up to date", "Built earlier. It rebuilds when you open it", "Not built yet. It builds when you open it", "Build failed", or "Building…" with the clock, and it updates when a build ends. Its old labels described live editing, not the build.
- A build that dies inside your browser (it stops making progress, or its output cannot be saved) is now written to the engine log, so a bug report shows it.

## 🔗 An app can hand a short name to the app it opens
`molfarShell.openApp(id, view)` takes an optional `view`; the opened app hears it through `molfarShell.onView`, also when it was not running yet. It is meant as the short id of work handed over from one app to another. An older engine opens the app and drops the view. Nothing changes for you until an app uses it.

## Other changes
- The app-authoring skill describes `view`; the handbook pages on apps and the shell, and the guide page on apps, describe the build line and the Developer labels.

## 📦 What arrives through app updates
Roleplay and Social are released from their own repositories; press **Update** in the Updates dialog to get their latest versions.

## How to get it
From source: `git pull && bun install && (cd client-agent && bun install) && bun run build:client`, then restart. Downloads and the Android APK are on this release page. See [CHANGELOG.md](https://github.com/MolfarWav/Molfar.Vertep/blob/main/CHANGELOG.md).
