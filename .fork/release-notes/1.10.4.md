# 🧩 Molfar Vertep 1.10.4

The Dashboard reads whole replies and now tracks the same person, thing or place as one. Every person, thing and place in a chat gets one identity that the Dashboard, the World DM, Litopys and agents share. Agents can also change Dashboard fields, and a chat no longer jumps to its oldest message while you read. This is **Roleplay 4.88.0, an app update**; the engine itself has no code changes in this release. **Order:** get this engine release and restart, then open Updates and press Update on Roleplay.

## 👥 One person stays one person
- The Dashboard used to make two characters out of one person: "Queen Seraphina" and "Seraphina", "Sina Rose" and "Sina", "Kaede Fuji" and "Каэде". Now every name the Dashboard reads is matched to the people the chat already has: the cards, including a narrator card with a whole cast; their sections and nicknames; the Souls; and the names your character has had. A match can be the exact name, the same name in another alphabet, one word of a full name, or a name one letter off. A card title or a narrator ("Campus Sluts", a long speaker label) never becomes a character.
- A doubtful pair is never joined silently. The Person tab shows "X may be the same person as Y" with the reason, and the "Since your last reply" row gets a "Possible duplicate" chip. **Merge into Y** moves the notes, history and things to Y and keeps X's name as another name of Y's. **Different people** keeps the two apart for good.
- To join two characters yourself, use the small people button in a character's header: "Same person as..." (you are asked first). "Remove from the Dashboard" in the same menu takes off a name that is simply wrong.
- A chat that continues another keeps the same people.

## 👗 The Dashboard reads the whole reply
- Every message used to be cut to its first and last 750 characters, so the clothes and events in the middle of a long reply never reached the Dashboard (a reply of 4 to 5 thousand characters lost most of its text). The Dashboard now reads new messages whole, up to about 12,000 characters together; only the middle of a very long reply is cut. Litopys and the World DM read messages the same way now.
- Before the model reads a reply, code marks the sentences that look like clothing, shoes, putting on or taking off, a kiss or an embrace, or something held (a bag, a phone, a vial, an axe, a dagger) in about a dozen languages, and points the model at them. When a sentence names nobody ("She leaned over, her short skirt riding up"), the hint says which character the paragraph named just before it. Names written in another alphabet are recognised too. You can add words for another language in `data/dashboard/lexicon.json`.
- If a card has an "Attire:" line, the Dashboard also sees it as a reference for the exact wording of a garment the text mentions. It never adds a garment the text does not show.
- When the story has not shown what someone wears for about six turns, the writing model is asked to mention it, briefly.

## 🗝️ A thing stays the same thing, wherever it goes
- What a character wears and holds is now a list of items, each with its own identity. A torn gown stays one gown. Sneakers taken off at the door are still the same sneakers when she puts them on again. An axe handed to someone else moves with them, and nothing is ever both in someone's hands and lying on the floor.
- A place keeps what was left in it: when the story returns to the café, the cup is still on the table. Two rooms of one house are two places, and a house is not the street in front of it.
- The World DM and the Dashboard now mean the same thing even when they name it in different languages ("a vial of murky liquid" and "пузырёк с мутной жидкостью"). The World DM sees the Dashboard's identities and ties its records to them.
- Only real objects are listed as things lying in the scene, never a creature, a puddle, a stain or a spell. A garment's name stays the garment, not the scene around it.
- Chats made before this update are carried over on their next reply. A garment that got two identities in the first test version is one again.
- These changes come with a new Dashboard sensor prompt (version 20). It reaches you unless you edited the sensor prompt; an edited prompt keeps working.

## 🤖 Agents can change Dashboard fields
- The Agent forge has a **Write to Dashboard** card (palette group Dashboard). An agent can set a character's mood, condition, outfit, held things, goal or relationship numbers, or the scene's place and weather, with optional limits for numbers. Each field needs its own permission.
- The agent line under a reply lists every change (`trust: 42 → 55`) with **Undo** while the Dashboard has not moved on. If a message is read again, the change is kept.
- An agent finds a character by any of their names in the chat ("Rhea" for "Rhea Faeth").

## 🛠️ Fixes
- **A chat no longer jumps to its oldest message while you read further up** (#241, reported on Discord for Brave). After a reply, the Dashboard, Litopys, the World DM and agents refresh the chat in the background. A refresh that came while one of them was saving the chat could read it as empty for a moment, which threw the reader to the top. An empty read no longer replaces a chat on screen, and your reading position is kept when the messages are refreshed. It was checked in Chromium on desktop and phone widths, not in Brave itself.

## Other changes
- The Dashboard guide page is updated and translated again for the 13 other languages.
- The engine has no code changes. Notes for the next session are in the repository (`.fork/STATE.md`).
