# 🧾 Molfar Vertep 1.3.3

Molfar works in several chats at once, tells you when you are away, can tidy your chats, and asks a model again when its connection drops. This is an engine release: Roleplay is unchanged.

### 🧵 Several chats at once (#69)
**New chat**, or opening another chat, no longer stops a run: it goes on in the background, and opening the chat again shows its text as it is written. In the chat list a chat that is not open has a mark: a spinner while it works, an amber **?** when it waits for your answer, a green check when it finished while you were elsewhere (until you open it). A strip under the header names those chats, so a question that waits is not missed on a phone, where the list is behind the drawer. A page opened in the middle of a run (a reload, another tab) shows the run as working and its message.
The engine refuses a second run in a chat that is already working (a message there is a correction) and the deletion of a working chat. There is no limit on parallel runs: a rate-limited free model shows its own error in that chat.

**Chats that share files know about each other.** When Molfar's file tools change a file that another chat, still working, changed too, the tool's result says so: which task, how long ago, and the `git log` to look at. Nothing is added to the prompt. Changes made through shell commands are not tracked.

### 🔔 Notifications
When you are not looking at Molfar (another window or tab, a minimized browser, or another Molfar Vertep app in front), the browser shows a notification when **Molfar asks you something**, **finishes in a chat**, **stops with an error**, or a chat you are not in **begins to wait for your answer**. A click brings the window forward and opens that chat. On by default for each browser; the browser asks for its permission at your first click in the shell or in Molfar's page. **Settings → Molfar → Notifications** has the switch, the permission state and **Send a test**. The Android app does not show them (its web view has no notifications API).

### 🗂️ Molfar looks after your chats
A new `chats` tool: ask Molfar to list your chats (by words in the title, or the ones not used for a month), archive or bring back, rename, move into a project or out of one, or delete. **Delete always shows a card** with the names and dates and waits for your Delete; it never touches the chat the request came from or a chat that is working. The tool stays hidden until needed, so it takes no room in the prompt. Also closed: Molfar's file tools could overwrite a chat transcript in `agent/` (outside git, no way back); `agent/` is now read-only for them.

### 🔌 A dropped model connection is asked again
A free provider closing the socket on a long chat ended the run with "The socket connection was closed unexpectedly. For more information, pass `verbose: true`…". The call is now asked again up to three times (after 2, 6 and 15 seconds); the words the broken call had written are taken back and a note says why the page waits. If all tries fail, the error says in plain words that the connection closed and what to do: send again, compact the chat, or pick another model.

### ✅ Apply proposal
The button under a reply shows only in **Plan** mode, where Molfar proposes and changes nothing, and pressing it leaves Plan mode before it sends the message.

### Known
- After a reload in the middle of a run, the reply shows only the words streamed since the reload until the run ends.
- A mark in the chat list moves the title about 20 px.
- A background chat is stopped by opening it; there is no Stop button on its row.
- If the browser does not ask for the notification permission, press **Send a test** in Settings.
