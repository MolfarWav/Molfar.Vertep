# 🧬 Molfar Vertep 1.10.0

Characters now have a journal: what they think, how they see the people around them, and what they want after a scene. The Dashboard clock also stops falling behind. This is **Roleplay 4.86.0, an app update**; the engine itself has no code changes in this release. **Order:** get this engine release and restart, then open Updates and press Update on Roleplay.

## 📓 A journal for every character
- The story model used to get facts, numbers and what a character saw, but never what the character **thinks of it and wants because of it**. Now each character present in a scene has a one-line **thought** (first person, in the story's language), and a line about **each person they know** (the player too) when something changed how they see them. They come from the Dashboard's own call: no extra model call. The cost is about 360 more input tokens per Dashboard call, plus one short line per character per turn on the output.
- A thought **fades**: it goes into the reply prompt only for 3 turns (you can change that), and the Dashboard never shows its own previous thought to the model, so a thought does not stick the way a goal once did. A thought written from the character's own values can be a grudge or a doubt; it is not flattery.
- Memories of closed scenes from Litopys now exist in a scene with **just you and one character**, and say what the character **wants now**.
- Where to see and control it: the **Journal box in the open Dashboard** (read-only for now: right now, people, entries; not in the narrow strip or the phone sheet); **Dashboard settings, Journal**: on or off, in the prompt or not, how long a thought lasts (1 to 10 turns), the budget per character (40 to 400 tokens, default 120); a per-chat switch on the prompt board; and the prompt inspector shows it as its own part, "Dashboard · journal". The history reserve counts it.
- Not measured yet on a live paid model. The wording of the sensor rules for the thought is the first thing to tune.

## 🕘 The Dashboard clock (#207)
- **The date stopped falling a day behind.** When the story jumped to "the next morning" without a day number, the clock put the morning on the *same* day, so every date after it was a day short. A time of day well before the clock's now moves the day on.
- **The model no longer invents its own hour.** The Dashboard ran a clock from the start of the part of the day ("about 09:00"), but the prompt said only "morning", so the model made up an hour and could say it was already noon. The prompt now says "about 09:00, morning".
- **A scene where your character is alone** used to give the model no Dashboard block at all, so no date, time or place; it now carries the scene line.
- Known and left: the clock runs slow by design (it adds the sensor's estimate of minutes each turn and only a stated time corrects it); when the sensor has not yet read the newest reply, the prompt carries the older clock.
