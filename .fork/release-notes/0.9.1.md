# 🎭 Molfar Vertep 0.9.1

Molfar gets cheaper, quicker and better at cards. The same card task that took 49 model calls and 1.5M input tokens in 0.9.0 now takes 6 to 9 calls and 0.1–0.2M. Molfar also learns the craft of characters, lorebooks and presets. On Android, updates now install over the app, and bash works on the phone.

## ✨ What's new

### 🃏 Molfar knows how to write cards (Roleplay 4.26.0, through app updates)
Open **Updates** in the top bar to install Roleplay 4.26.0. It brings four skills that Molfar loads when a task needs them:
- **card-craft**: a new character from an idea, or a deeper one. Description and personality kept apart, a first message that sets the length and tone of the story, example dialogue that shows the character under pressure, and what makes a character flat, repetitive or speak for you.
- **card-import**: a card or lorebook from JanitorAI, RisuAI, Wyvern or pasted text, adapted to this app. Files the app imports by itself (PNG and JSON cards, chub.ai links, SillyTavern world info) still go through **Import**.
- **lorebook-craft**: a world that holds together and entries that fire, with keys in every inflected form people type.
- **preset-craft**: writing, auditing and porting presets.

All four point to one reference of the card, lorebook and preset files, so Molfar no longer goes looking through the app's code to learn them. The character editor shows the card's **id** with a copy button: give it to Molfar and it edits exactly that card.

### 💸 Far fewer tokens per task
Most of Molfar's cost came from reading too much and from calling the model again for every small step. Now:
- **Single fields of a card or lorebook.** Molfar reads and changes one field of a big card (`json_get`, `json_set`) instead of the whole file with its portrait. A whole new lorebook is written in two calls, and a JSON file can no longer be left broken.
- **Big JSON shown as its fields.** Opening or @-mentioning a card gives Molfar its fields and their sizes, not tens of kilobytes of base64.
- **Shorter calls.** Old steps and earlier tasks shrink to short notes, the skills list is lighter, and app-building instructions arrive only when Molfar works on an app's code.
- **Fewer retries.** A busy provider (429 or 5xx) is retried by itself, and the sandbox traps that cost extra calls are gone.

### 🧭 Molfar's page, easier to use
- **"/" menu**: it scrolls, groups commands and skills by where they come from, and searches their descriptions too (`/lore` finds the lorebook skills).
- **"@" finds characters, lorebooks and presets by name**, not only files: pick "Dzvinka" and Molfar gets the exact card.
- **Quick actions** above an empty composer: New character, Improve a card, Write a lorebook, Audit a preset, Import a card. Each one starts the request with the right skill.
- **Steps folded by default**: reasoning and tool calls show as one line ("Working · 3 tool calls · json_set"), so the answer stays on screen. Tap the line to see the steps.
- **More room**: a wider chat column, and the composer stays at the bottom in a new chat too.
- **On a phone** the model name has a row of its own instead of being cut to one letter.

### 📱 Android: updates install over the app
The APK is now signed with the project's own key, so a new version installs over the old one and keeps your data. **Get update** in the app downloads the new APK itself, checks that it is really our release (size, checksum, package and signing key) and hands it to Android, which asks you to confirm. The first time, Android asks you to allow Molfar Vertep to install apps.

**One-time step for installs of 0.9.0 and earlier:** they were signed with a throwaway key, so Android refuses to update them in place ("App not installed"). Do this once:
1. In Molfar Vertep, open **Settings → Backup** and save a full backup (with a password, so your API keys are in it).
2. Uninstall the app and install the 0.9.1 APK.
3. Restore the backup in **Settings → Backup**.

From then on, updates install over the app.

## 🛠️ Fixes
- **Android:** bash and the file tools work. Every file looked "outside the workspace" because the app's folder is reached through a link (`/data/user/0`), so `read_file` refused everything and bash saw an empty `/workspace`.
- A profile restored from a backup installs its apps' packages at once. Before, Roleplay failed to build (fonts, react) until the next restart.
- Updating an app no longer fails with an error about `dist.discard-…`. The old build is moved out of the app before it is deleted, which mattered most on slow phone storage.

## Other changes
- Release archives are named `Molfar-Vertep-<version>-<system>`; self-update finds both the old and the new names.
- The README is rewritten for people new to the project, with Ukrainian and Russian translations.
- The Docker image builds from the renamed archives.

## ⬇️ How to get it
- **Launcher users:** run `Molfar-Vertep.bat` and answer **Y** to "Update to release v0.9.1". Then open **Updates** in the top bar for Roleplay 4.26.0.
- **Running from source otherwise:** pull the tag `v0.9.1`.
- **Downloads** below: `Molfar-Vertep-0.9.1-<system>` for desktops and `Molfar-Vertep-0.9.1-android-arm64.apk` for Android 9 and newer (see the one-time step above if you have an older APK installed).
- **Docker:** `ghcr.io/molfarwav/molfar-vertep:v0.9.1` or `:latest`.
