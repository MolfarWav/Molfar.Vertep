# 🖼️ Molfar Vertep 1.7.0

A feature release: sharper expression sprites with no limit on how many a card holds, Gemini as a picture backend, and fixes to how imported SillyTavern presets and hidden reply blocks are handled. Roleplay 4.74.0 rides with it as an app update. **Order:** get this engine release and restart, then open Updates and press Update on Roleplay. The sprite, preset and hidden-block changes all live in Roleplay, so they arrive with that update.

### 🧍 Sprites keep their quality, and a card can hold as many as you like (#167)
Expression sprites used to be squeezed so they would fit inside the card file: 256 px when you added them in the editor, 192 to 768 px when they came with an imported card (the whole pack was shrunk until it fitted 2.8 MB), and anything over 700 KB or a 3 MB pack was dropped. Now every sprite goes into the engine's picture store as a WebP with its transparency, up to 1024 px on the long side, and the card keeps only a short link to it. PNG and other formats are converted on the fly, so a file takes a fraction of the space it did as a PNG.
- Adding sprites in the editor (one at a time, or a whole pack by file name) stores them at full quality.
- Importing a card or a CHARX pack (including RisuAI packs) no longer shrinks or drops sprites: a test pack of 30 sprites at 1500 px each, 36 MB in total, imported with all 30 intact.
- Sprites you already have keep working. They move to the new store the next time you change that card's sprites.
- A picture in the store first fails once inside the app frame and then loads; the sprite panel and the avatar in a message used to give up at that first failure, so they now wait a few seconds. A sprite whose picture is really gone hides the panel and shows the default avatar, as before.
- Exporting a card as CHARX includes the sprites. A plain JSON or PNG export now carries links to the store instead of the picture itself, so use CHARX when you move a card with its sprites to another install.
Not checked yet: a real phone, and your own large packs. Tell us if 1024 px is not the size you want.

### 🍌 Gemini for pictures (#62)
Add a Google (Gemini) key in Connections and the Imagen and Gemini Image ("Nano Banana") models your key can use appear in the image model list, so Molfar's image tool, Roleplay and Settings > Images can use them like any other. The list is read live from Google. A wrong key, a prompt the model refuses and a picture Imagen filtered each come back as a plain sentence. Nano Banana already worked through OpenRouter; this is the direct route. Not tried against a live key yet: tell us if a model is refused. The empty-state hint in Settings > Images still says "OpenRouter or NanoGPT".

### 📜 Imported SillyTavern presets keep the card's post-history instructions (#85)
A preset imported from SillyTavern names its post-history slot `jailbreak`, and Roleplay only filled the card's post-history instructions for its own slot, so they never reached the model. Now that entry fills the slot: the card's text wins, `{{original}}` in it stands for the preset's own text, and with no card text the preset's text goes out. Presets you imported before work as they are, with no re-import.

### 🎭 Narrator groups can write for you when the preset says so (#85)
In a group where one narrator voices several characters, the engine always added "Never write your words or actions". Presets for auto, guided or co-writing modes asked for the opposite. The line now ends "unless the preset's instructions say otherwise", so those presets are no longer contradicted.

### 🫥 Hidden reply blocks no longer eat the Dashboard and Litopys (#85)
Many presets have the model write blocks that are hidden from you (a plan, an inner voice, a focus log) and strip them with regex scripts. The Dashboard sensor and Litopys cut each reply to its first 1500 characters before reading it, so a long reply spent those characters on hidden blocks. They now read a reply the way the model does: the preset's prompt-only scripts that delete a block run first. Your stored chat text is never changed. Scripts that use macros, depth limits or a replacement are left alone.

## 🛠️ Fixes
- When one plugin call runs out of memory and the shared worker is restarted, the other calls in flight now get an error that names the plugin and route that did it, instead of a bare "worker exited". A read that was only a bystander is run again on the new worker (#162).
- Stopping a generation no longer doubles your message (#119): this shipped in Roleplay 4.66.0 and is confirmed on real use; the issue is closed.

## Other changes
- Issue #89 (backup pictures, Undo with data, refused draft) shipped in 1.4.1; it is closed with the write-up.
- The card skill `edit-large-card` knows sprites can be store links; paste `.fork/handoff/sprites/workspace-agent-task.md` into Molfar to update your own copies.

## How to get it
From source: `git pull && bun install && (cd client-agent && bun install) && bun run build:client`, then restart, then Update on Roleplay in Updates. Downloads and the Android APK are on this release page. See [CHANGELOG.md](https://github.com/MolfarWav/Molfar.Vertep/blob/main/CHANGELOG.md) for details.
