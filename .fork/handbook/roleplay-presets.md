# Presets: the format, the prompt board, the stock presets, import and shaping
Verified at: molfar.vertep-roleplay 607147f

## What it does
A preset is the prompt around a chat plus its sampler settings, stored as `data/presets/<id>.json` in the SillyTavern prompt-list shape with a `studio` bag holding the editor's full copy. `presetToEngine` writes the file from the editor's type. When a reply is built, `assemble` turns the chat's preset, variable picks and prompt board switches into messages, depth injections and sampler parameters.

## The preset file
- `id` (same as the file name) and `name`.
- `prompts`: `identifier`, `name`, `role`, `marker`, `content`; depth injection uses `injection_position: "absolute"` with `injection_depth`. A non-empty `content` on a marker entry (`main`, `chatHistory`, ...) replaces the engine's text.
- `prompt_order`: `[{character_id, order: [{identifier, enabled}]}]`. The engine reads 100001 first, then 100000, then the first non-empty list.
- Top-level samplers (`temperature`, `top_p`, `top_k`, `min_p`, penalties, `seed`, wider textgen keys), `openai_max_tokens`, `samplers_override_model`, `reasoning`, `reasoningTags`, `thinkingBudget`.
- `studio`: `sections` (with `condition`, `injectionTriggers`, `locked`), `groups`, `variables` (`choice`, `toggle`, `text`, `number`, `slider`), `samplers`, `promptFormat`, shaping fields, `readOnly`, `isDefault`.
- `openai_max_context` in a file is ignored; the model's window applies.

## Stock presets
- Four built-ins: `frankenx`, `molfar`, `vertep-lite`, `vertep-medium`. Each has a read-only copy `data/presets/<id>.json` and a template `data/presets/_<id>.json`. The generic list route skips names starting with `_`.
- `vertep-lite` is generated by `scripts/vertep-lite.ts`, which writes both files with identical bytes: edit the script, run `bun scripts/vertep-lite.ts`. No script builds the other three (grep found none); their JSON is kept by hand. Regex scripts sit in `data/regex/` with templates `data/_vertep-medium-regex.json` and `data/_molfar-regex.json`.
- `data/presets/default.json` has no `studio` bag; the boot code in `src/lib/store.ts` rewrites such a file in the app shape.
- Update: `onAppUpdate` runs once after the app version moves. For each of the four ids, when the stock file and its template both carry `studio.readOnly: true` and differ, the template overwrites the stock file. Regex templates only add scripts whose id is missing.
- User edits: `updatePreset` refuses changes to a read-only preset, so user work lives in a `duplicatePreset` copy (new id, `readOnly: false`). The refresh needs `readOnly: true` on both sides, so an editable copy is never overwritten.

## Import, the report, the diff
- The Import button calls `importPreset`, which calls `presetImportFull`. Order: own format (`studio` bag with `sections`), Marinara, then SillyTavern (needs a `prompts` array). Anything else throws "Not a recognizable preset file".
- Missing fields come from a base preset: the one open in the editor, else the first editable one.
- The import gets a new id, `readOnly: false` and a unique name ("Name (2)"). Its regex scripts get scope `preset` and the new id.
- The report has buckets `came`, `approx` and `dropped`, plus a source tag. Each line is text under `presetReport.<id>`.
- Diff: `PresetDiffDialog` compares the open preset with another preset in memory, not with files. Sections match by name.
- Export (`presetExport`) drops `readOnly`, `isDefault` and `folderId` from the `studio` bag.

## How a reply reads the preset
1. `assemble` loads `presets/<chat presetId>.json`, or the default preset if that file is gone, and budgets against the model's window.
2. `resolvePresetVars` gives each variable the chat's stored pick, else its default.
3. It walks `orderedPrompts` and skips entries that are switched off, switched off on the prompt board, failing a `condition`, or whose `injectionTriggers` lack this generation type.
4. Markers take engine text (card, persona, world info, examples); non-empty preset content replaces it. The card's system prompt replaces `main` unless `forbidOverrides` is set. Macros expand through `expandMacros`.
5. Entries with `injection_position: "absolute"` join the history at their depth, counted from the newest message.
6. History goes at its marker, or after the other parts. A trailing assistant section becomes the prefill.
7. Shaping applies to messages: names, compact history, post-processing, system squashing.
8. Top-level numbers go into `presetParams`; seed, stop strings and logit bias come from `studio.samplers`. Reasoning settings and `verbosity` ride with the request.
9. `cutInlineThinking` removes thinking tags from saved replies; the prompt board's thinking switch strips them from history.

For a new chat, `presetMemory` and the user's picks in `preset-defaults.json` supply the preset and picks, unless the new-chat step sent its own.

## If you change X, also touch Y
- A field on `Preset` (`src/lib/types.ts`): `presetToEngine`, `enginePresetToUI`, the reader in `assemble`, and `presetExport`.
- A stock preset: its `_<id>.json` template and its file. A new stock id must join the loop in `onAppUpdate`; `test/rp-chat-features.test.ts` lists the built-ins.
- A prompt board switch key: `PROMPT_BOARD_OFF_KEYS` or `PROMPT_BOARD_OFF_RE`, and the carries strip (`docs/COUPLINGS.md`).
- The persona line in the built-in presets: `personaFrame` in `assemble` (`docs/COUPLINGS.md`).

## Traps
- An empty object from the new-chat step is truthy, so `stepVars || ...` skips per-character memory and the user's default picks.
- `presetToEngine` writes a top-level `stop`, but no reader of it appears in `plugins/engine/plugin.js`; stop strings come from `studio.samplers.stopStrings`.
- Only the string `"absolute"` makes a depth injection. Raw SillyTavern numeric `injection_position: 1` is read as a normal section.
- `default.json` writes `prompt_order` as a flat list the engine skips, so every section is on.
- `importPreset` saves the preset before the regex batches, with no rollback.
- A file without `samplers` takes the open preset's numbers.
- The diff matches sections by name; two sections with one name show as one row.
- The engine's preset `PUT` does not enforce `readOnly`; only `updatePreset` does.
